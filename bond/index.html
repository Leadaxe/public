LX Bond

1

Why

DDR §1

LX Bond is a core feature: it spreads the packets of a single flow over the network interfaces it is given and reassembles them on an aggregation node in a data centre, so one TCP download can use the sum of the channels' bandwidth. In practice that means 3–10 channels; the hard limit is 16 paths per session, and the limits, overhead budgets and tests are sized for that worst case. Bond takes interfaces as input and assumes nothing about the hardware behind them. Per-connection balancing over several interfaces already works with core features; bond adds packet-level bonding on top. Operators' DPI cuts recognisable tunnels (WireGuard, OpenVPN, IPsec), so each channel is an ordinary sing-box tunnel (vless+REALITY, XHTTP, hysteria2, tuic, wg, masque) bound to one interface, and bond frames ride inside those tunnels. The node runs the same sing-box binary with a bond inbound; traffic exits with the node's address, through a primary or a standby DC.

Non-goals: no wire compatibility with MPTCP or Multipath QUIC, no L2 bridging, no server-initiated paths, no business logic on the node beyond the inbound, nothing in the public repository.

2

Topology

DDR §1.2, §4.7, §11

The client is a bond endpoint: a TUN-like L3 device (gVisor stack) that receives IP packets from routing. It owns N paths; each path is a detour to an ordinary outbound whose leaf carries bind_interface for one interface. Every path dials the node's bond listener at its public address (a WG stack drops loopback destinations, and a masque path exits at the far tunnel end). On the node, the path's proxy inbound (wg, hysteria2, vless) hands the stream or datagrams to the bond inbound, which joins the paths into one session, reassembles, and emits packets into the router. One session terminates on one node; paths are never split across nodes.

The nodes are the servers list, each with its own address, key, device address and paths. Paths belong to a server because in the reference deployment the proxies run inside that node's process and die with it. Servers are tried by priority; equal priorities are ordered at random once at start, so clients spread over equal nodes. A failover is a new session with a new sid.

3

Keys and handshake

DDR §1.2, §3.2–3.5

Identity is a static X25519 key pair, WireGuard-style. The client config holds its own private_key and, in each servers entry, that node's public_key; the node holds its private_key and the list users[].public_key. Keys are bare base64 (44 characters), compatible with sing-box generate wg-keypair. An optional pre_shared_key is mixed in as psk2 and is never the identity.

Each path runs its own Noise IKpsk2 handshake (X25519, ChaCha20-Poly1305, BLAKE2s), WireGuard's construction with the cleartext handshake header bound into the prologue. All paths handshake in parallel, one round trip each. The client chooses the 128-bit sid; each side assigns the pcid it wants to see on frames it receives (client_pcid in INIT, server_pcid in RESP).

The frame

DDR §2.1–2.3

Every frame on every path carries the same fixed 14-byte header, big-endian, no varints. The header is cleartext and authenticated as AAD; the body is encrypted; a 16-byte tag closes the frame. On stream paths each frame is preceded by a 2-byte length. pcid buys rebinding without path death and ts buys the timer-free release rule and the deviation guard. Hover or focus a field.

5

Scheduler: earliest delivery

DDR §5.3–5.7

The sender does not round-robin. For each frame at the head of the ingress FIFO it predicts, per path, when the frame would arrive, and sends it where it lands first:

A(p, s) = owd_min_p + q_model_p + q_exo_p + s/btl_p

q_model is the queue our own sends built (it reacts instantly); q_exo is the smoothed queue we did not cause (radio scheduler, proxy, HOL). When the fastest path f is cap-blocked, a slower path g is used if it still delivers first counting the backlog B waiting behind the head (ECF with the backlog term, Lim et al. 2017), or if f has been saturated for one srtt_f and g's lateness fits the BLEST budget (Ferlin et al. 2016). The budget starts at κ·reorder.max_latency = 0.8 × 200 ms and adapts once per feedback delay.

BDP_p  = btl_p · ack_min_p
cap_p  = max(BDP_p, clamp(1.25·BDP_p + btl_p·T_report, 4·max_frame, cap_ceiling_p))

The inflight cap is BBR's cwnd_gain·BDP plus the bytes acknowledged but not yet reported within one interval. The 1.25 gain is a default because LTE acknowledgement batching and DRX delay feedback to verify on the stand: R-1. Cold start seeds btl at 1 Mbit/s and grows per srtt round with BBR's STARTUP gain 2/ln 2 ≈ 2.89, for at most 2 s.

Every pick also writes a ring entry {dsn, pcid, A_f, A_g, lateness, reason} with reason ∈ {fast, alt, wait, blest, cold, dup, fallback, announce}, sampled 1-in-N under load. The FIFO is bounded at 50 ms × Σbtl (64 KiB…4 MiB) and is scheduled strictly in order; a held head frame waits at most hold_max = 4 ms before the rule is re-run.

6

Receiver: lost or late

DDR §6.1–6.4

Every frame carries two numbers: the session-wide DSN (release order) and its path's PSN (per-path loss accounting), as MPTCP's DSN/SSN. The receiver releases strictly by DSN from its cursor R. A path covers R once it has delivered a frame enqueued after R with no undecided hole below it; because every frame is stamped inside one critical section, DSN (or the dsn_high cover of a control frame) increases with PSN on every path.

hole h on p is lost on p   when  now − t_after(h) ≥ reo_wnd_p            (RACK time threshold)
reo_wnd_p  = clamp(max(4·dev_p, reo_learned_p), 2 ms, reo_max_p)        reo_max 20 → 60 ms
pending(R) = { p live ∧ covering : R > cleared(p) }
pending(R) = ∅  →  R is lost, not late: skip it now, no timer             (accounted_lost)
guard: deadline(R) = S_min(R) + max_{p ∈ pending(R)} (owd_eff_p + max(4·dev_p + 2 ms, 5 ms)),  ceiling 200 ms

The guard is clocked from the frames' own sender timestamps and the pending paths' current one-way delay, with a silence term so a path in a handover holds the release up to the 200 ms ceiling instead of releasing frames that are still in flight. A frame that arrives after its DSN was released is delivered anyway (TCP above handles reordering better than a drop) and counted as late_after_release on its path.

7

Feedback

DDR §7.1–7.5

The receiver sends a REPORT every T_report = 15 ms (allowed 10–20 ms) while frames arrive, or early once 32 frames arrived and at least 2 ms passed since the last one. Nothing is sent when nothing was received. A REPORT is 49 + 41·n bytes: a 19-byte fixed part (release cursor dsn_next, free reorder bytes, wait and depth, cumulative guard and late counters) and one 41-byte record per path with new frames, aligned to the arrival of psn_high. It travels on the path with the smallest reverse delay; a second copy goes to the second-best path every 4th report and on every event report. PATH_ACK carries one record on its own path (≤ 1 per max(T_report, 50 ms)) to give a same-path RTT sample. If no report arrives for 2·T_report + srtt_best (floor 50 ms) while frames are outstanding, the sender sends FENCE R on every live path.

Overhead at 4 paths and 15 ms: ≈ 180 kbit/s per direction before encapsulation, ≈ 1.5–2× on the wire on a WG path; at 16 paths ≈ 0.6–0.8 Mbit/s per direction to verify on the stand: R-10.

8

Redundancy

DDR §5.9, §8

The policy is a hybrid by traffic class, in RAID terms. Bulk is striped (RAID 0) and never duplicated. Small critical packets (≤ 200 bytes including the IP header) are duplicated (RAID 1) on a second path with flag D and the same DSN; the receiver keeps the first copy. FEC (RAID 5/6: systematic Reed–Solomon over GF(2^8)) arrives in v1 on top of striping, at a rate that grows with measured bursty loss and is off on clean channels.

TierMatches (len ≤ 200 B)Budget
1 priorityTCP SYN, FIN or RST; ICMP/ICMPv6; port 53 or 853; the first datagram of a new UDP flowone token bucket for all tiers: 10 % of the last second's data rate, floor 20 kbit/s; tiers 2–3 stop at 25 % of the bucket so the next SYN is never starved
2 budgetpure ACKs of flows whose reverse direction is < 1 Mbit/s; DSCP EF (46) or AF41–43; duplicate.ports; v1: TCP retransmissions, RTP-like UDP
3 user (v1)DSCP values in duplicate.dscp
nevereverything else, and every packet above max_size; no duplicate: "all" is offered

FEC rate law (v1). Per path the sender estimates a Gilbert–Elliott chain: loss fraction π_p and mean bad-period duration T_bad_p in seconds, converted to a burst length in symbols at the current frame rate. Group size k = clamp(round(10 ms · f_fec), 4, 32) follows the offered non-duplicated frame rate; the repair count r is the smallest one whose residual, computed exactly per path on the Gilbert–Elliott chain, meets a target of 0.1 %, counting repair losses on the same chain as the members, never above floor(k·30 %) or the wire maximum 8. FEC turns on when the traffic-weighted loss Σ w_p·π_p ≥ 0.2 % for at least 1 s with at least 8 loss runs counted, and off below 0.05 % for 10 s. If 30 % overhead cannot at least halve the loss, FEC goes off, the lossy paths are demoted, duplicates stay, and with every path lossy the session falls back. Worked example from the DDR: at mean burst L = 3 and r = 6 the residual is 26.3 % of the raw loss.

Lower bound. fallback mode puts all primary DATA on the one path with the best expected goodput (mean rate × (1 − loss) over 5 s, never lowest delay), tier-1/2 duplicates on the second, FEC off, every other path exempt and probed. It is entered when estimates go stale, reports vanish, late releases exceed 5 %, or the delivered rate stays below 0.9 × the best single path while the FIFO is busy; it is left only after a 2 s re-probe predicts ≥ 1.1 × the fallback path.

Path life

DDR §4.1–4.7

The sender judges its paths from the receiver's records. A path is suspect when frames above psn_high are outstanding and the oldest has waited longer than rto_p = srtt_p + 4·rttvar_p + T_report (floor rto_min 50 ms, no ceiling); the clock restarts on every record that advances psn_high, so a single lost frame never makes a delivering path suspect. Suspect for dead_after = 1.5 s (an LTE handover and a 1.28 s DRX paging cycle, not an uplink reboot) means dead. Demotion to backup uses factor 2 against the median of the other active paths; promotion needs factor 1.5 held for promote_after = 10 s. A returning path re-enters as backup for return_hold, 10 s doubling per death within 10 min up to 60 s.

Handshake timing: INIT at t0, retransmitted at +1 s and +3 s with fresh ephemerals, handshake_timeout at +7 s. A dead path re-dials on its own backoff 1, 2, 4 … 30 s ±20 %. With no path established the session runs handshake cycles on every path at once and backs off 5 → 60 s between them. Keepalive is one FENCE K per live datagram path every 25 s (below common CGNAT UDP timeouts); it is the only timer that runs while idle.

Observability

DDR §12

Status follows the core's rule for endpoints: a unary GetBondStatus(tag) getter in the lx command protocol, not a field in GetOutbounds and not a tick in a stream. The node gets GetBondInboundStatus(tag, filter, page) (64 sessions per page by default, 256 max), and a separate GetBondDebugDump(tag, ring, max_bytes) returns one ring per call (1 MiB default, 3.5 MiB hard cap under grpc-go's 4 MiB limit). Metrics are raw facts: cumulative counters, monotonic stamps, ages and rates computed at read; every release and drop reason is its own counter. Carriers are gRPC over the lxd mTLS listener and the CLI api bond / bond-inbound / bond-dump; the stand collector polls 1–5 s and pulls dumps before every scripted stop.

Event ring

  • 4096 × 64 B per endpoint/inbound; events never sampled out, scheduler picks 1-in-N so the ring covers ≥ dead_after + max rto_p + 1 s.
  • Two incident slots: the first since start and the latest (rewritten ≤ once per 10 s). Freeze on suspect/dead, mode change, guard storms, overflow, stream stall, FENCE-R.
  • Nothing is persisted across stop/apply.

Closed vocabulary

  • path dialing | handshake_ok | confirmed | probing_done | active | demoted(variance|loss|queue|mtu) | suspect(no_progress|write_block) | dead(report_timeout|conn_error|…)
  • session established | mode(…) | failover(from, to, reason) | return_to_primary | epoch_change
  • receiver release_guard | release_overflow | late_after_release | report_path_switch
  • Log line: path 2 (lte-b) dead reason=report_timeout srtt=84ms outstanding=37 gen=3

The status seam

The gRPC service and its proto belong to the sing-box core. The private bond build adds the status schema to it through go build -overlay: it adds the handler file with its stub and the CLI file, and replaces the two generated pb files with versions generated from the private proto (the public proto plus the bond block). The public core carries no bond schema. The pb files are regenerated on every core sync; CI compares the public part of the private proto with the core's proto and fails on drift.

Verification

DDR §16

Level 1 is primary: the maths is verified there before any stand is built. Every gate judges what the model or the stand did, in ground-truth terms, never the bond's own estimates.

Acceptance targets

TargetCriterion
Aggregatesteady-state goodput per direction ≥ 85 % of Σ single-path baselines (same traffic, same stand, measured right before) over 30 s after the first 5 s; 90 % stretch
Reorder latencyP99 wait ≤ Δ_true + J99 + 10 ms at every level; Level 1 against the oracle: P99 ≤ 5 ms loss-free, ≤ reorder_window_max + 5 ms (65 ms) lossy
Death recoverylast DATA on the failed path ≤ 2·srtt_true + 100 ms after injection; 8 bulk flows back to ≥ 90 % of the survivors' Σ base within 2 s; dead within 2 s for RTT ≤ 200 ms
Re-joinactive within min(1.2·outage, 36 s) + 6 s for outages of 2–60 s

CPU≤ 1 low-end arm64 core (Cortex-A55 class) per 100 Mbit/s with AEAD both ways to verify on the multi-uplink bench

Run cost: the frame tier runs thousands of scenarios in seconds at reduced rates; a TCP-tier run costs up to ≈ 20 CPU-s. Whether gVisor's goroutines park in a way testing/synctest counts as durably blocked is to verify first; if not, bond builds its own stack with a manual clock.

Routing on the node: who may go where

Bond only says who came (the key, passed on as auth_user = users[].name) and from which address (checked against users[].address). Where the user may go is the node's route rules. Without rules the default is open: data-centre networks, services on 127.0.0.1 and the node's own public address are reachable from every client, so each node config ends with a default reject.

"route": {
  "rules": [
    {"inbound": ["bond-in"], "auth_user": ["client-0042"], "ip_cidr": ["10.1.0.0/16"], "outbound": "office-wg"},   // one user to an internal network
    {"inbound": ["bond-in"], "source_ip_cidr": ["10.77.255.0/24"], "ip_cidr": ["10.0.100.0/24"], "outbound": "mgmt"},  // a role by address pool
    {"inbound": ["bond-in"], "ip_is_private": true, "action": "reject"},                                             // RFC 1918, ULA, loopback, link-local
    {"inbound": ["bond-in"], "ip_cidr": ["100.64.0.0/10", "198.51.100.10/32"], "action": "reject"}                   // CGNAT space and the node itself
  ],
  "final": "direct"
}

A server is a node as a whole: address, key, the device address on that node and its own paths; no node is special and none inherits from another. Objects inside bond are named by name; tag stays a sing-box reference. transport is derived from the detour (tcp for vless, trojan and other stream-carried leaves, udp otherwise) and can be overridden. Per path there is no bind_interface (the leaf outbound carries it), no server, no tls and no policy override.
